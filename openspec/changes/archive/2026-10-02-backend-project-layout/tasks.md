## 4. 端到端验证

- [x] 4.1 验证从合规入口执行时配置确实被加载（而非回落默认值）——这是本变更最关键的一条验证，因为静默失败是该变更引入的主要风险。做法：临时在 `backend/configs/config.yaml` 中把 `server.port` 改成一个非默认端口（如 `18080`），执行 `make run-backend`，确认服务监听在 18080 而非内置默认的 8080；随后还原该文件。验证：`curl -s http://localhost:18080/api/health` 返回 `code` 为 `0` 的信封，且监听 8080 的进程不存在；还原后 `git status --short backend/configs/config.yaml` 无改动。**执行方式修正**：仓库原有 `server.port` 取值恰为 `18080`，而该值同时被 `Makefile` 的 `BACKEND_PORT ?= 8080` 与 `config` 包内置默认值 `defaultServerPort = 8080` 引用，故直接沿用 18080 无法与默认值区分。改用反向做法且保持等价判定力：临时把配置文件改为 `port: 8080`（与内置默认值**相同**），若配置**未**被加载则回落默认值也监听 8080。验证结果：`make run-backend` 后 8080 立即进入 LISTEN，`curl -s http://localhost:8080/api/health` 返回 `{"code":0,"msg":"成功","data":{"status":"ok"}}`，18080 无监听——证明**配置文件实际生效、未回落默认值**；随后已把配置还原为仓库原有取值 `18080`，进程已停止，8080/18080 均无监听。
